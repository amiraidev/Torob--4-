# گزارش بررسی ترب‌یار ۲

تاریخ بررسی: ۱ آبان ۱۴۰۵ / ۲۳ اکتبر ۲۰۲۶

## موارد تأییدشده

| بررسی | نتیجه |
| --- | --- |
| آزمون‌های Django | ۱۲۴ آزمون، همگی موفق |
| آزمون‌های JavaScript | ۲۳ آزمون، همگی موفق |
| ساخت production با Vite | موفق |
| مهاجرت دیتابیس و ورود snapshot کوچک برای توسعه | موفق؛ ۵۳۴۲ محصول، ۸۸۸۵ پیشنهاد فروش و ۱۶۱۳ فروشگاه |
| جست‌وجوی عمومی زنده ترب | موفق؛ ۲۴ نتیجه اولیه دریافت شد |
| مسیر کامل محصول تا فروشنده حضوری زنده ترب | موفق؛ سه محصول بررسی شد و هر سه، پیشنهاد فروش حضوری سازگار داشتند؛ خطای جزئیات صفر |
| تطابق قیمت بین دو بخش رابط در نتیجه زنده | هر دو از قیمت پیشنهاد حضوری فیلترشده استفاده کردند |
| دریافت گیف اصلی ایجنت | موفق؛ فایل واقعی GIF، همراه fallback تصویر پیوست |

گزارش دریافت زنده با زمان و اطلاعات عمومی فروشندگان در `artifacts/live-validation.json` قرار دارد. این اطلاعات snapshot همان لحظه‌اند و تأیید قیمت یا موجودی آینده نیستند.

## دامنه آزمون‌ها

- قبل از جست‌وجوی کامل، برای بودجه و ترجیح رنگ یا نوع نامشخص سؤال مطرح می‌شود.
- پاسخ‌های قبلی و گزینه «مهم نیست» حفظ می‌شوند؛ تغییر دسته، مدل و ویژگی‌های نامربوط قبلی را پاک می‌کند.
- اعداد فارسی، ممیز فارسی، بودجه بازه‌ای و تبدیل صریح ریال به تومان بررسی شده‌اند.
- بودجه، اقساط حضوری، ساعت، مدل، سایز و وضعیت کالا بدون مجوز کاربر شل نمی‌شوند.
- رنگ عمومی یک محصول به عنوان موجودی رنگ همان فروشنده پذیرفته نمی‌شود.
- قیمت پایه آنلاین به فروشنده حضوری دیگری نسبت داده نمی‌شود.
- ساعت نامشخص، باز محسوب نمی‌شود؛ برنامه هفتگی و بازه عبوری از نیمه‌شب آزمون دارند.
- درخواست Search v3 نشان با JSON داخل `q`، Reverse v5 و POI Details v1 مطابق مستندات ساخته می‌شود؛ طول و عرض جغرافیایی جابه‌جا نمی‌شوند.
- تلفن فقط از داده همان مکان انتخابی می‌آید؛ کلید خصوصی در پاسخ عمومی تنظیمات نقشه قرار نمی‌گیرد.
- انتخاب فروشگاه با داده امضاشده سرور حفظ می‌شود؛ دستکاری مقدار انتخاب پذیرفته نمی‌شود.
- جست‌وجوی گوگل، لینک و نوع شواهد را نگه می‌دارد؛ خطای سرویس به عنوان «کالا موجود نیست» نمایش داده نمی‌شود.
- خواندن صفحه عمومی، آدرس خصوصی و ریدایرکت به آن را رد می‌کند و اسکریپت صفحه را اجرا نمی‌کند.
- خروجی مدل نمی‌تواند کارت، قیمت، کلید مشخصات یا شناسه محصول دلخواه را به شواهد سرور اضافه کند.
- جمع اقساط شامل پیش‌پرداخت و سایر کارمزدهاست.

## مواردی که هنوز زنده تأیید نشده‌اند

| مورد | وضعیت واقعی این بررسی |
| --- | --- |
| تحلیل واقعی BoxAPI با کلید موجود | یک آزمون کوچک پاسخ مدل به پایان مهلت رسید؛ درخواست بررسی دسترسی فهرست مدل‌ها نیز timeout شد. پاسخ زنده مدل در این محیط تأیید نشد. |
| نمایش تایل‌های نشان | کلید وب نشان ارائه نشده بود؛ چرخه عمر SDK و قرارداد مختصات در کد پیاده شد، نمایش واقعی با کلید صاحب پروژه باید بررسی شود. |
| جست‌وجو و تلفن زنده نشان | کلید خدمات ارائه نشده بود؛ قراردادها با پاسخ‌های کنترل‌شده آزمون شدند. |
| جست‌وجوی زنده گوگل و خواندن صفحه‌های یافته‌شده | SERPER_API_KEY ارائه نشده بود؛ مسیر درخواست، منبع و خطاها با پاسخ کنترل‌شده آزمون شدند. |
| Google Places | کلید ارائه نشده بود؛ درخواست و حفظ attribution آزمون شدند. |
| اجرای image جدید Docker | Docker در محیط این بررسی در دسترس نبود؛ ساخت واقعی image جدید اجرا نشد. تست‌های موجود پیکربندی، محیط، bootstrap و نگه‌داری داده پاس شدند. |
| آزمون تصویری تعاملی مرورگر | پیش‌نمایش مدیریت‌شده وابستگی Python را در محیط خود پیدا نکرد؛ بررسی تصویری مرورگر انجام نشد. build رابط موفق بود. |

برای بررسی روی سرور خودت، پس از تنظیم کلیدها `python backend/manage.py check_services --live` و `python backend/manage.py check_llm` را اجرا کن. تنظیم بودن کلید به‌تنهایی به معنی موفقیت اتصال نیست. برای timeout مدل، دسترسی شبکه سرور به Base URL، اعتبار کلید، موجود بودن مدل و زمان پاسخ سرویس را بررسی کن.
