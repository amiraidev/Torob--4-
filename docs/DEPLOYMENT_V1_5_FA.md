# ترب‌یار ۱٫۵ — نسخه کم‌حجم با راه‌اندازی خودکار Docker

این بسته از فایل `Torob.zip` خودت اصلاح شده است. React، Django، داده‌های کامل و تنظیمات BoxAPI همراه آن هستند. کلید موجود در فایل تو حفظ شده و لازم نیست دوباره واردش کنی.

## استقرار مستقیم روی لیارا

۱. برنامه موردنظر را با پلتفرم **Docker** باز کن.

۲. همین ZIP را آپلود کن؛ `Dockerfile` و `liara.json` باید در ریشه ZIP باشند.

۳. پورت برنامه را **8000** انتخاب کن و استقرار را شروع کن.

برای استفاده عمومی از چت و جستجو، ساخت دیسک یا اجرای دستی setup، migrate، import و build لازم نیست. دامنه‌های `torob-yar-v2.liara.run` و `torob-yar.liara.run` آماده‌اند. نام برنامه یا تیم دیگری در فایل استقرار تحمیل نشده است.

دیتاست کامل به قالب فشرده و از پیش پردازش‌شده تبدیل شده است. Docker آن را به صورت جریانی می‌خواند و دیتابیس و ایندکس‌ها را می‌سازد؛ CSV حجیم همراه بسته نیست. مرحله آماده‌سازی داده در محیط آزمون حدود ۲۲ ثانیه بود؛ نصب وابستگی‌ها و ساخت رابط، زمان جداگانه دارند و به منابع و شبکه میزبان وابسته‌اند. هنگام start داده‌ها دوباره وارد نمی‌شوند.

پس از استقرار بررسی کن:

- [صفحه برنامه](https://torob-yar-v2.liara.run/)
- [وضعیت برنامه](https://torob-yar-v2.liara.run/api/health/)

اگر برنامه‌ات روی دامنه دوم است، همان مسیرها را با `torob-yar.liara.run` باز کن.

## اجرای Docker روی کامپیوتر

Docker Desktop را اجرا کن. ZIP را استخراج و در پوشه آن اجرا کن:

```bash
docker compose up --build -d
```

یا در ویندوز روی `run-docker.bat` بزن. پس از آماده شدن کانتینر، [http://localhost:8000](http://localhost:8000) را باز کن. Python، Node، pip و npm روی میزبان لازم نیستند.

وضعیت و لاگ:

```bash
docker compose ps
docker compose logs -f web
```

توقف با حفظ داده‌ها:

```bash
docker compose down
```

برای اجرای عادی، volume را حذف نکن. Compose دیسک `torob_storage` را خودش ایجاد و به `/app/storage` متصل می‌کند. پورت میزبان را در صورت اشغال بودن می‌توانی با `TOROB_HTTP_PORT` تغییر بدهی؛ پورت داخلی سرویس همان 8000 است.

## دیتابیس بدون دیسک و با دیسک

| حالت | روش کار |
| --- | --- |
| لیارا بدون دیسک متصل | دیتابیس کامل داخل image، فقط‌خواندنی و بدون کپی سنگین در فضای موقت استفاده می‌شود؛ چت، جستجو، مقایسه و نقشه کار می‌کنند. |
| لیارا با دیسک متصل به `/app/storage` | خودکار به دیتابیس قابل‌ویرایش روی دیسک تغییر می‌کند؛ شروع اولیه، migration و افزودن داده‌های گمشده خودکار است. |
| Docker Compose | volume خودکار دارد و دیتابیس قابل‌ویرایش و کلید Django را حفظ می‌کند. |

دیتاست کامل شامل **۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ پیشنهاد فروش و ۶٬۴۷۶ فروشگاه** است. فایل SQLite آماده از حدود **۶۵۹ به ۲۹۴ MiB** کاهش یافته است. برای پایگاه تازه قابل‌ویرایش، دیسک ۱ گیگابایتی برای این snapshot و فضای عملیات معمول مناسب است؛ برای ارتقای دیتابیس بزرگ نسخه قبلی، ۲ گیگابایت فضای آزاد در نظر بگیر تا کپی موقت migration و VACUUM جا داشته باشد.

همه رکوردها و مقادیرشان حفظ شده‌اند؛ هش محتوای هر سه جدول با نسخه قبلی برابر است. مشخصات و سایر سندهای JSON بدون اتلاف با UTF-8 و zlib ذخیره می‌شوند. متن اصلی جستجو در ایندکس FTS دوباره کپی نمی‌شود و دو ایندکس اضافه کلید خارجی حذف شده‌اند؛ ایندکس‌های ترکیبی همان جستجوها را پوشش می‌دهند. فشرده‌سازی برای ویرایش‌ها و ورود داده‌های بعدی نیز فعال است.

در فایل `data/catalog.jsonl.xz`، پیشنهادها کنار محصولشان قرار دارند و به فروشگاه‌ها با ارجاع کوتاه اشاره می‌کنند. شناسه عمومی، قیمت، مشخصات، تصویر و فروشگاه هنگام بازسازی عیناً برمی‌گردند. بارگذاری جریانی، بررسی SHA-256، کنترل تعداد رکوردها و کلیدهای خارجی، ساخت گروهی ایندکس‌ها و آزادسازی صفحات اضافی خودکارند. فایل CSV ZIP قدیمی کنار این داده نگه‌داری نمی‌شود.

جستجو ابتدا قیمت و شرایط قابل بررسی در SQL را اعمال می‌کند. مشخصات و تصاویر فقط برای کارت‌های نهایی خوانده می‌شوند و اطلاعات هر فروشگاه در همان درخواست یک بار پردازش می‌شود. این بهینه‌سازی، زمان پاسخ مدل BoxAPI یا شبکه ترب را تضمین نمی‌کند. پیش‌نمایش مستقل نیز با gzip فشرده شده و وارد image تولیدی نمی‌شود.

در لیارا برای ویرایش داده‌ها با Django Admin یا ذخیره تغییرات سرور، یک دیسک به `/app/storage` وصل کن و برنامه را مجدداً راه‌اندازی کن. در حالت فقط‌خواندنی، تغییرات پایگاه و ساخت حساب مدیریتی امکان‌پذیر نیست. گفت‌وگوها و محصولات ذخیره‌شده رابط خرید در مرورگر خود کاربر نگه‌داری می‌شوند.

داده‌ها و کلید موجود روی دیسک با restart حذف نمی‌شوند. در آپدیت، رکوردهای موجود با داده بسته بازنویسی نمی‌شوند و رکوردهای گمشده افزوده می‌شوند. برای بازگردانی عمدی snapshot باید از پایگاه تازه استفاده کنی.

برای تعیین صریح حالت، متغیر `TOROB_DATA_MODE` مقادیر `auto`، `readonly` و `persistent` را می‌پذیرد. پیش‌فرض `auto` است. برای اجرای معمول نیازی به تغییر آن نیست.

## BoxAPI و محل کلید

این تنظیمات از فایل `.env` همراه بسته خوانده می‌شوند:

| متغیر | مقدار |
| --- | --- |
| `LLM_BASE_URL` | `https://ai.boxapi.ir/ai/v1` |
| `LLM_MODEL` | `prism-ml/ternary-bonsai-2-27b` |
| `LLM_API_KEY` | همان کلید موجود در فایل ارسالی خودت |
| `LLM_ENABLED` | `true` |
| `LLM_TIMEOUT` | 45 ثانیه برای هر درخواست مدل |
| `LLM_MAX_TOKENS` | 2200 |
| `LLM_JSON_MODE` | `false` |

این نسخه برای خواسته «فقط فایل‌ها را بگذارم» عمداً فایل خصوصی را در مرحله نهایی image، در `/app/config/runtime.env` قرار می‌دهد. فقط متغیرهای مدل از آن خوانده می‌شوند؛ تنظیمات توسعه، میزبان localhost و کلید ضعیف توسعه وارد تنظیمات انتشار نمی‌شوند. فایل خصوصی وارد build فرانت‌اند یا پوشه‌های عمومی و static نمی‌شود.

**این ZIP، فایل .env و image ساخته‌شده شامل کلید خصوصی تو هستند؛ آن‌ها را عمومی منتشر نکن.** کلید در رابط React، پاسخ API و لاگ برنامه چاپ نمی‌شود.

اگر کلید را تغییر دادی، خط `LLM_API_KEY` داخل `.env` را ویرایش و image را دوباره build کن. پیش‌فرض، تنظیمات مدلِ فایل از متغیرهای قدیمی پنل اولویت بیشتری دارند؛ بنابراین `LLM_ENABLED=false` یا مدل قدیمی پنل، فایل صحیح تو را بی‌صدا غیرفعال نمی‌کند.

اگر می‌خواهی کلید و مدل را از متغیرهای خصوصی پنل مدیریت کنی، `LLM_CONFIG_SOURCE=environment` را قرار بده و مقادیر `LLM_*` را در پنل ثبت کن.

بررسی اتصال از داخل کانتینر:

```bash
docker compose exec web python /app/backend/manage.py check_llm
```

در ترمینال لیارا:

```bash
cd /app/backend
python manage.py check_llm
```

این فرمان یک درخواست کوچک واقعی به حساب مدل می‌فرستد و ممکن است اعتبار مصرف کند. هیچ کلیدی چاپ نمی‌شود. در پاسخ چت، `llm.analysis_used=true` به معنی انجام تحلیل مدل برای همان پیام است. `llm_configured=true` در health فقط کامل بودن تنظیمات است.

## Docker چه کارهایی را انجام می‌دهد؟

در build، وابستگی‌های Python در محیط مجزای کوچک و وابستگی‌های Node نصب، React ساخته، دیتاست فشرده به SQLite تبدیل، شاخص جستجو آماده و staticهای Django جمع‌آوری می‌شوند. فقط وابستگی‌های Python به مرحله نهایی کپی می‌شوند تا یک کپی اضافه از کل runtime Python ساخته نشود. هیچ API مدل در build فراخوانی نمی‌شود.

در start، پورت و دامنه و حالت انتشار یکسان می‌شوند، کلید قوی Django در محل مناسب ساخته یا خوانده می‌شود و حالت داده انتخاب می‌شود. در صورت وجود volume، دیتابیس اولیه نصب و migration و merge بدون حذف ویرایش‌های قبلی انجام می‌شود. سپس Gunicorn روی `0.0.0.0:8000` اجرا می‌شود.

healthcheck فقط وضعیت خود برنامه و آماده بودن کاتالوگ را می‌سنجد؛ قطع شدن BoxAPI باعث restart بی‌مورد کانتینر نمی‌شود. اجرای برنامه بعد از آماده‌سازی دیسک، با کاربر عادی کانتینر انجام می‌شود.

## منبع جستجو و تحلیل

Django داده را از ترب دریافت می‌کند و مدل همان شواهد را تحلیل می‌کند. مدل خودش ابزار مرور وب مستقل ندارد. اگر ارتباط زنده ترب قطع باشد، جستجو به دیتاست کامل برمی‌گردد و منبعِ فایل و خطای زنده در رابط مشخص است.

پیشنهاد فروش و قیمت، حتی وقتی از ترب دریافت شده‌اند، تضمین موجودی امروز نیستند. ساعت نامشخص، باز بودن فروشگاه محسوب نمی‌شود. فاصله خط مستقیم است. ویژگی‌ها و قیمت کارت از داده واقعی می‌آیند و با خروجی مدل جایگزین نمی‌شوند؛ متن توضیح مدل همچنان ممکن است خطا داشته باشد.

مدل ترجیحات و تاریخچه شامل سؤال‌های نمایش‌داده‌شده و ترتیب کارت‌ها را دریافت می‌کند. تحلیل با تغییر فیلتر نیز اجرا می‌شود. سؤال تکمیلی متناسب با کالا، مشخصات مستند و موارد نامشخص جداگانه نمایش داده می‌شوند.

## مدیریت و توسعه

پس از اتصال دیسک قابل‌ویرایش، حساب مدیر را خودت بساز؛ حساب یا رمز پیش‌فرض ناامن وجود ندارد:

```bash
docker compose exec web python /app/backend/manage.py createsuperuser
```

برای اجرای توسعه خارج Docker، همچنان `python scripts/setup.py` و سپس `python scripts/run.py` وجود دارند. این مسیر به Python و Node میزبان نیاز دارد؛ برای اجرای Docker آن‌ها را انجام نده.

برای ارتقای پایگاه نسخه قبل روی volume، migration یک بار اسناد را فشرده و فضای آزادشده را بازپس می‌گیرد؛ رکوردهای کاربر حفظ می‌شوند. در شروع‌های بعد این عملیات تکرار نمی‌شود. پیش از ارتقای یک پایگاه دارای ویرایش شخصی، از volume پشتیبان بگیر.

برای جایگزینی عمدی دیتاست با ZIP/CSV جدید در محیط توسعه و انتشار مجدد:

```bash
python scripts/build_seed.py --dataset path/to/new-dataset.zip --output work/catalog.sqlite3
python scripts/pack_catalog.py work/catalog.sqlite3
```

سپس image را دوباره build کن. فرمان بسته‌بندی پایگاهی را که حساب کاربری دارد قبول نمی‌کند تا رمزها و حساب‌های مدیریتی همراه snapshot منتشر نشوند. برای راه‌اندازی عادی هیچ‌یک از این فرمان‌ها لازم نیست.

وضعیت آزمون‌ها و محدودیت بررسی محیط در [DOCKER_VALIDATION_FA.md](DOCKER_VALIDATION_FA.md) ثبت شده است.
