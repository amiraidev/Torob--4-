# ترب‌یار ۳ — ایجنت هوش مصنوعی برای گفت‌وگو و مقایسه خرید

این نسخه روی پروژه اصلی `Torob.zip` ساخته شده است: React + Django، دیتاست فشرده کامل، جست‌وجوی زنده ترب و تنظیمات مدل قبلی حفظ شده‌اند. کلید مدلِ موجود در فایل خصوصی `.env` حفظ شده است. برای قابلیت‌های جدید، کلید نشان و جست‌وجوی گوگل را اضافه کن.

## اجرای سریع با Docker

۱. فایل ZIP را استخراج کن. فایل `.env` کنار `Dockerfile` را ویرایش کن.

۲. کلیدهای زیر را در همان فایل قرار بده. مقدار نمونه را با کلید واقعی خودت جایگزین کن:

```dotenv
LLM_ENABLED=true
LLM_BASE_URL=https://ai.boxapi.ir/ai/v1
LLM_API_KEY=YOUR_PRIVATE_AI_KEY
LLM_MODEL=prism-ml/ternary-bonsai-2-27b
LLM_TIMEOUT=45

NESHAN_MAP_KEY=YOUR_NESHAN_WEB_MAP_KEY
NESHAN_SERVICE_KEY=YOUR_PRIVATE_NESHAN_SERVICE_KEY
SERPER_API_KEY=YOUR_PRIVATE_SERPER_KEY
# اختیاری؛ برای اطلاعات کسب‌وکار و شماره تماس از Google Places
GOOGLE_PLACES_API_KEY=

PUBLISH_PHONE_CONTACTS=true
WEB_RESEARCH_ENABLED=true
WEB_PAGE_FETCH_ENABLED=true
```

اگر مدل و کلید قبلی‌ات را نگه می‌داری، سه خط `LLM_BASE_URL`، `LLM_MODEL` و `LLM_API_KEY` را بی‌دلیل جایگزین نکن.

۳. Docker Desktop را اجرا کن و در ریشه پروژه بزن:

```bash
docker compose up --build -d
```

برنامه در `http://localhost:8000` اجرا می‌شود. دیتابیس در volume نگه‌داری می‌شود.

```bash
docker compose logs -f web
docker compose down
```

## دریافت و تنظیم کلیدهای جدید

| متغیر | کاربرد | محل استفاده |
| --- | --- | --- |
| `GOOGLE_MAPS_BROWSER_KEY` | اختیاری؛ کلید محدود به دامنه برای Google Maps Embed | عمومی در مرورگر؛ مستقل از کلید خصوصی Places |
| `NESHAN_MAP_KEY` | نمایش تعاملی نقشه وب نشان | عمومی در مرورگر؛ آن را به دامنه‌های خودت محدود کن |
| `NESHAN_SERVICE_KEY` | جست‌وجوی مکان، تبدیل GPS به آدرس و دریافت تلفن/ساعات کاری مکان | فقط Django |
| `SERPER_API_KEY` | جست‌وجوی واقعی گوگل از طریق Serper | فقط Django |
| `GOOGLE_PLACES_API_KEY` | جست‌وجوی کسب‌وکار در Google Places API (New)، شماره و آدرس | فقط Django؛ اختیاری |
| `LLM_API_KEY` | تصمیم‌گیری، انتخاب ابزار، سؤال و مقایسه توسط مدل انتخابی | فقط Django |

- نشان: [مستندات رسمی](https://platform.neshan.org/docs/). کلید وب نقشه و کلید خدمات جدا هستند. خدمات Search v3، Reverse v5 و POI Details v1 باید برای کلید خدمات مجاز باشند. طبق مستندات فعلی نشان، فعال‌سازی Search v3 ممکن است به تیکت پشتیبانی نیاز داشته باشد.
- برای کلید وب، دامنه توسعه و دامنه واقعی خودت مثل `torob-yar-v2.liara.run` را مجاز کن. دامنه‌های مجاز را مطابق پنل نشان تنظیم کن.
- جست‌وجوی گوگل: [Serper](https://serper.dev/). این سرویس کلید مستقلی می‌خواهد؛ کلید مدل AI جای آن قرار نمی‌گیرد.
- اطلاعات گوگل‌مپ: [Google Places Text Search (New)](https://developers.google.com/maps/documentation/places/web-service/text-search). فعال بودن API و مجوزهای حساب سرویس خودت لازم است. بدون این کلید هم خدمات نشان می‌توانند شماره و آدرس ثبت‌شده را برگردانند.

## جریان ایجنت هوش مصنوعی

مسیر اصلی رابط `POST /api/agent/chat/` است. مدل در هر نوبت یکی از سه کار را انتخاب می‌کند: سؤال تکمیلی، فراخوانی ابزار یا پاسخ نهایی. پس از اجرای ابزار، نتیجه واقعی به مدل برمی‌گردد تا قدم بعدی را انتخاب کند. این مسیر، جست‌وجوی ثابت با یک خلاصه AI در انتهای آن نیست.

- ابزارها: جست‌وجوی محصول/فروشنده در ترب یا منبع انتخابی کاربر، دریافت جزئیات محصول‌های شناخته‌شده، تحقیق گوگل و خواندن صفحه عمومی، یافتن فروشگاه، جزئیات مکان، آدرس محدوده GPS و محاسبه اقساط اعلامی کاربر و اختلاف قیمت پیشنهادی مغازه.
- مدل خواسته‌ها و پاسخ‌های کوتاه را از گفت‌وگو استخراج می‌کند، اطلاعات ناقص را می‌پرسد و برای همان نیاز، محصولات و فروشندگان را انتخاب می‌کند. تغییر فیلتر سخت باید به عبارتی از پیام کاربر ارجاع داشته باشد؛ بودجه عددی با واحد گفته‌شده دوباره بررسی می‌شود.
- برای مقایسه، کنار حداقل دو محصول روی آیکون ترازو بزن و «مقایسه با AI» را انتخاب کن؛ یا در چت بگو «اولی و دومی را برای کار من مقایسه کن». دکمه مقایسه، شناسه محصولات را به مدل می‌فرستد؛ مشخصات دلخواه مرورگر، شاهد معتبر محسوب نمی‌شوند.
- AI معیارها، ارجحیت‌ها، پیشنهاد نهایی، دلایل انتخاب و نکات نامشخص را می‌نویسد. سلول‌های جدول از ارجاع به داده سرور پر می‌شوند؛ مدل عدد سلول را تولید نمی‌کند. انتخاب هر فروشنده نیز باید متعلق به همان محصول و سازگار با فیلترها باشد.
- امتیاز قاعده‌ای قدیمی در مسیر ایجنت حذف شده است. کارت دارای رتبه AI فقط زمانی برچسب انتخاب مدل دارد که مدل برای آن فروشنده و دلایل مستند انتخاب کرده باشد. ترتیب نمایش «قیمت» و «فاصله» مطابق انتخاب کاربر حفظ می‌شود.
- در خطای مدل، پیام «تحلیل AI تکمیل نشد» و دکمه تلاش دوباره نمایش داده می‌شود؛ تحلیل قاعده‌ای به‌عنوان AI عرضه نمی‌شود. داده‌ای که پیش از خطا دریافت شده ممکن است با برچسب نتیجه دریافت‌شده نمایش داده شود.

پروتکل، JSON روی API سازگار با Chat Completions است و به پشتیبانی native function calling وابسته نیست. مدل باید بتواند JSON معتبر و دستورهای چندمرحله‌ای تولید کند؛ کیفیت تفسیر زبان و توصیه‌ها به مدل انتخابی بستگی دارد. کنترل شناسه و منبع، به معنی تضمین صحت تمام استدلال‌های متن آزاد مدل نیست.

پیش‌فرض هر نوبت حداکثر ۶ درخواست مدل و ۴ درخواست ابزار است. جست‌وجوی زنده حداکثر ۳ محصول پایه و ابزارها حداکثر ۸ نامزد را برای مقایسه در اختیار مدل می‌گذارند؛ این پوشش کل بازار نیست. بودجه شبکه هر ابزار حداکثر ۴۰ ثانیه، مهلت هر پاسخ مدل ۲۵ ثانیه و مهلت شروع مراحل بعدی کل نوبت ۱۷۰ ثانیه است. زمان‌بندی DNS، پردازش محلی و پاسخ‌های شبکه می‌تواند بر زمان واقعی اثر بگذارد. این محدودیت‌ها از اجرای بی‌پایان جلوگیری می‌کنند؛ یک گفت‌وگو ممکن است چند درخواست قابل‌محاسبه در سهمیه مدل مصرف کند.

اطلاعات عمومی محصولات بین نوبت‌ها در `agent_state` فشرده و امضاشده، با اعتبار پیش‌فرض ۳۰ دقیقه حفظ می‌شود؛ مختصات دقیق کاربر و فاصله محاسبه‌شده در این توکن ذخیره نمی‌شوند. این روش به حافظه یک worker خاص وابسته نیست و با SQLite فقط‌خواندنی هم کار می‌کند. تاریخ انقضا به معنی تازه بودن قیمت نیست. تاریخ قیمت و وضعیت snapshot همچنان باید بررسی شوند.

## صحبت کردن و شنیدن پاسخ

روی میکروفون بزن، فارسی صحبت کن، متن تشخیص‌داده‌شده را مرور و ویرایش کن و سپس ارسال را بزن. میکروفون خودکار شروع نمی‌شود. «شنیدن پاسخ» متن توضیحی AI را می‌خواند. این نسخه گفتار را از API مرورگر می‌گیرد؛ سرویس صوتی مستقل یا مکالمه صوتی پیوسته سرور ندارد. پشتیبانی تشخیص فارسی، اتصال سرویس گفتار و وجود صدای فارسی به مرورگر و سیستم‌عامل بستگی دارد. ممکن است مرورگر صدا را به سرویس آنلاین خودش بفرستد. HTTPS یا localhost و مجوز میکروفون لازم است؛ تایپ همیشه در دسترس است.

## تحقیق و منابع

دریافت محصولات و قیمت‌ها همان سرویس Django است. رنگ/مدل/قیمت به همان پیشنهاد فروش تعلق دارند. مسیر عمومی ترب قرارداد API تجاری تضمین‌شده نیست و ممکن است تغییر یا محدود شود. منبع زنده در خطا خودکار به دیتاست تبدیل نمی‌شود.

مدل در صورت نیاز ابزار تحقیق گوگل را انتخاب می‌کند؛ این ابزار کلید Serper می‌خواهد. حداکثر دو صفحه عمومی با رعایت robots.txt و محدودیت حجم/زمان خوانده می‌شوند. خلاصه جست‌وجو، تست عملی مستقل یا تأیید موجودی/تلفن/اقساط نیست. درخواست ابزار و وضعیت واقعی آن در گزارش ایجنت قابل مشاهده است.

## فیلترها

حداقل و حداکثر قیمت، دسته/نوع محصول، مدل، برند، رنگ، سایز، وضعیت کالا، فقط باز، فاصله، اقساط حضوری، ترب‌پی حضوری و ارسال فوری در دسترس‌اند. مرتب‌سازی قیمت و فاصله در سرور حفظ می‌شود و مدل آن را عوض نمی‌کند.

دو تب «پیشنهادهای حضوری» و «قیمت بازار ترب» از فیلترهای یکسان استفاده می‌کنند. قیمت تب دوم اکنون قیمت همان فروشنده حضوری سازگار با فیلتر است؛ کمترین قیمت نامرتبط آنلاین به آن نسبت داده نمی‌شود. تعداد محصولات بررسی‌شده محدود و در پاسخ مشخص است؛ نتایج، ادعای پوشش همه بازار نیستند.

تطبیق رنگ و سایز باید در متن همان پیشنهاد فروش دیده شود. فهرست رنگ‌های عمومی یک مدل، موجودی رنگ یک مغازه محسوب نمی‌شود. وضعیت نو/کارکرده نیز باید در عنوان همان کالا یا اعلام فروشنده شواهد داشته باشد. اطلاعات نامشخص در فیلتر سخت، پذیرفته نمی‌شود؛ کم‌شدن نتیجه در این حالت عمدی است.

## داخل فروشگاه یا پاساژ

روی «داخل فروشگاه هستم» بزن؛ نام مغازه، پاساژ و در صورت نیاز طبقه/واحد را وارد کن. موقعیت را با اجازه مرورگر یا انتخاب محله مشخص کن. در جزئیات هر فروشنده نیز دکمه تحقیق درباره همان فروشگاه وجود دارد.

- آدرس محدوده GPS از Reverse نشان دریافت می‌شود؛ دقت گزارش‌شده GPS همراه آن است.
- نتیجه‌های مکان نشان و Google Places جدا نمایش داده می‌شوند. نام و آدرس را تطبیق بده و فروشگاه درست را انتخاب کن. شماره فروشگاه هم‌نام یا شعبه دیگر به نتیجه انتخابی چسبانده نمی‌شود.
- برای نتیجه نشان دارای `poiHash`، جزئیات همان مکان شامل تلفن، وب‌سایت و ساعت ثبت‌شده گرفته می‌شود. ممکن است این فیلدها در منبع خالی باشند؛ شماره‌ای ساخته نمی‌شود.
- فروشگاه انتخاب‌شده برای ادامه راهنمایی تا پنج دقیقه با داده امضاشده سرور حفظ می‌شود. پس از انقضا، نتیجه تازه باید دوباره تطبیق داده شود.
- مراحل «یافتن و تماس»، «بررسی و تست»، «پرداخت و فاکتور» و «بعد از خرید» راهنمای متناسب دارند.
- اگر قیمت پیشنهادی فروشنده را وارد کنی و مدل قبلاً مشخص شده باشد، AI می‌تواند ابزار دریافت قیمت همان محصول را برای مقایسه انتخاب کند. اختلاف فقط با یکسان بودن مدل، ظرفیت، رنگ، وضعیت و گارانتی معنی دارد.
- در چت می‌توانی بگویی «مغازه این مدل را ۹۰ میلیون تومان گفته؛ مقایسه کن»؛ ابزار compare_quote اختلاف را با پیشنهاد همان محصول حساب می‌کند و قیمت گفته‌شده را با برچسب اعلام کاربر نگه می‌دارد. ماشین‌حساب اقساط، پیش‌پرداخت + تعداد اقساط × مبلغ هر قسط + سایر کارمزدها را با مبلغ نقدی مقایسه می‌کند. این محاسبه تأیید پذیرش اقساط یا وام نیست.

GPS داخل ساختمان معمولاً نمی‌تواند مغازه، طبقه یا واحد را قطعی تعیین کند. این اطلاعات در صورت اعلام کاربر، با همان برچسب باقی می‌مانند. ساعت ثبت‌شده هم تضمین حضور واقعی فروشنده نیست؛ پیش از حرکت، موجودی همان مدل و رنگ و شرایط پرداخت را تلفنی تأیید کن.

## نقشه و ظاهر ایجنت

گوگل‌مپ پیش‌فرض است؛ با انتخاب هر فروشگاه، مختصات همان فروشگاه روی گوگل نمایش داده می‌شود. گزینه **نشان** SDK رسمی Neshan MapLibre را باز می‌کند؛ مختصات آن به ترتیب `[longitude, latitude]` ارسال می‌شوند و لوگو و attribution حفظ شده‌اند. لینک گوگل و نشان کنار فروشگاه‌ها موجود است. لینک نشان از `https://nshn.ir/?lat=...&lng=...` استفاده می‌کند. اطلاعات مکان Google Places روی گوگل نمایش داده می‌شود؛ مختصات مستقل فروشندگان ترب روی هر دو نقشه قابل استفاده است.

بدون کلید وب نشان، پیام اتصال نشان و لینک بیرونی نمایش داده می‌شود. گوگل به‌صورت iframe ساده باز می‌شود؛ برای Maps Embed رسمی، کلید مرورگر اختیاری را تنظیم کن. دسترسی منطقه‌ای یا شبکه می‌تواند iframe گوگل را محدود کند؛ لینک مستقیم هم موجود است. دسترسی اینترنت، دامنه مجاز و اعتبار کلید برای نمایش تایل‌ها لازم است.

گیف اصلی `torob_radish.gif` به صورت محلی در بسته قرار گرفته و تصویر پیوست کاربر جایگزین خطای بارگذاری است. اندازه ۴۸/۵۶ پیکسل، نمایش pixelated و غیرفعال بودن drag مطابق نمونه ارسالی اعمال شده‌اند. فونت موجود پروژه حفظ شده است.

## اجرای ویندوز بدون Docker

Python 3.12 و Node 22 نصب کن و در پوشه پروژه اجرا کن:

```bash
python scripts/setup.py
python scripts/run.py
```

فایل `start.bat` هم مسیر اجرای قبلی را نگه داشته است. اجرای کامل داده‌ها در setup می‌تواند زمان ببرد. برای پیش‌نمایش کوچک توسعه، گزینه‌های اسکریپت setup را ببین؛ برای استقرار واقعی همان داده کامل بسته استفاده می‌شود.

## لیارا

پلتفرم Docker را انتخاب کن و محتوای ZIP را طوری آپلود کن که Dockerfile در ریشه باشد. دامنه‌های قبلی `torob-yar-v2.liara.run` و `torob-yar.liara.run` در پیکربندی حفظ شده‌اند. سرویس روی پورت داخلی ۸۰۰۰ اجرا می‌شود. در صورت استفاده از دیسک، آن را به `/app/storage` متصل کن. توضیح مدیریت داده و ارتقای بدون حذف رکوردها در `docs/DEPLOYMENT_V1_5_FA.md` نگه داشته شده است؛ تنظیمات جدید این README بر توضیحات قدیمی قابلیت‌های AI و نقشه اولویت دارند.

در پروفایل پیش‌فرض، `.env` خصوصی داخل کانتینر خوانده می‌شود. پس از ویرایش فایل، image را دوباره build کن. برای مدیریت کلیدها از متغیرهای خصوصی پنل، `SERVICE_CONFIG_SOURCE=environment` را تنظیم کن و کلیدها را در همان پنل قرار بده. این بسته حاوی فایل خصوصی قبلی است؛ برای انتشار عمومی سورس یا image، کلیدها را از نسخه عمومی خارج کن.

## بررسی اتصال و آزمون‌ها

بررسی تنظیمات بدون ارسال کلیدها به خروجی:

```bash
python backend/manage.py check_services
```

آزمون خواندنی سرویس‌های پیکربندی‌شده، با درخواست واقعی:

```bash
python backend/manage.py check_services --live --query "پاساژ چارسو"
python backend/manage.py check_llm
```

`--live` از سهمیه سرویس‌های پیکربندی‌شده استفاده می‌کند. `check_llm` یک درخواست کوچک به مدل می‌فرستد. در Docker، پیش از فرمان‌ها `docker compose exec web` بگذار.

```bash
python backend/manage.py test shopping

```

نتیجه بررسی نسخه ۳ در `VALIDATION_FA.md` آمده است؛ گزارش‌های قبلی در `docs/VALIDATION_V2_1_FA.md` و `docs/VALIDATION_V2_FA.md` حفظ شده‌اند. گزارش زنده ترب نیز در `artifacts/live-validation.json` قرار دارد. تست شبیه‌سازی‌شده با تأیید زنده تمام سرویس‌ها یکی نیست.

## مسیرهای جدید API

| مسیر | کار |
| --- | --- |
| `POST /api/agent/chat/` | مسیر اصلی گفت‌وگو و چرخه تصمیم‌گیری/ابزار/مقایسه AI |
| `POST /api/chat/` | مسیر قدیمی؛ برای سازگاری حفظ شده و پیش‌فرض رابط نیست |
| `POST /api/live-search/` | قیمت‌های ترب با همان preferences و location چت |
| `GET /api/map-config/` | فقط کلید عمومی و تنظیمات نقشه وب |
| `POST /api/places/search/` | نام مکان + location و نتیجه‌های جداگانه |
| `GET /api/places/<poi_hash>/` | جزئیات همان نتیجه نشان |
| `POST /api/position/` | مختصات به آدرس محدوده |

کلیدهای خصوصی مدل، نشان و گوگل در JSON این مسیرها یا build رابط قرار نمی‌گیرند. تاریخچه دقیق GPS و آدرس حاصل از آن در ذخیره محلی گفت‌وگو نگه‌داری نمی‌شوند. داده فروشگاه و متن صفحات، ورودی غیرقابل‌اعتماد مدل محسوب می‌شوند.

## قابلیت‌های حفظ‌شده از نسخه ۲.۱

- فیلترهای چت و قیمت بازار فرم یکسان دارند؛ حداقل/حداکثر نامعتبر با پیام روشن رد می‌شود.
- سؤال بودجه پس از دریافت نتایج، از قیمت‌های همان نتایج ساخته می‌شود؛ در نبود شاهد، بازه فرضی اعلام نمی‌شود.
- بازه‌هایی مثل «۲۰ تا ۳۰ میلیون» و دقت نامعتبر GPS هم اعتبارسنجی می‌شوند.
- محاسبه اقساط مقادیر منفی، تعداد نامعتبر و سرریز عدد را رد می‌کند.
- گفت‌وگوی جدید به ابتدای صفحه برمی‌گردد تا گیف ایجنت در موبایل هم کامل دیده شود.

برای نصب محلی ویندوز می‌توانی از `setup.bat` و سپس `start.bat` استفاده کنی. کلید AI قبلی موجود در فایل خصوصی پروژه حفظ شده؛ کلیدهای جدید را خودت وارد کن.

## تنظیم محدودیت‌های ایجنت

متغیرهای اختیاری `AGENT_MAX_STEPS=6`، `AGENT_MAX_TOOLS=4`، `AGENT_MODEL_TIMEOUT=25`، `AGENT_DEADLINE_SECONDS=170` و `AGENT_STATE_TTL=1800` در سرور خوانده می‌شوند. در چند worker باید کلید امضای Django مشترک و پایدار باشد؛ تنظیمات موجود Docker این کار را انجام می‌دهد. کلید خصوصی مدل در هیچ payload ارسالی به مدل، JSON عمومی یا فایل build رابط قرار نمی‌گیرد؛ هدر احراز هویت فقط توسط سرور ارسال می‌شود.
